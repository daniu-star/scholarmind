# 指令一致性规则（Instruction Consistency Rules）

> 循环式论文审稿优化Pipeline指令一致性保障模块
> 对应需求：避免出现多次滚回后遗忘指令的状态

---

## 一、指令一致性的重要性

### 1.1 为什么多轮循环后容易遗忘指令

循环式Pipeline通过多轮迭代打磨论文，但在多轮循环中存在指令遗忘与偏离的风险，主要原因包括：

| 风险来源 | 机制 | 后果 |
|---------|------|------|
| 上下文窗口限制 | 多轮对话累积超长上下文，早期指令被截断 | 初始指令的核心要求在后期轮次中被忽略 |
| 注意力衰减 | LLM对长上下文中早期内容的注意力权重衰减 | 初始指令的执行力度逐轮减弱 |
| 增量修改覆盖 | 后轮修改可能无意中覆盖前轮已合规的内容 | 已通过的章节出现回退 |
| 幻觉累积 | 多轮生成中可能引入初始指令未涉及的内容 | 论文出现事实性/引用性/方法性幻觉 |
| 指令漂移 | 多轮反馈意见可能与初始指令产生冲突 | 论文偏离原始研究意图 |

### 1.2 指令一致性的核心目标

- **初始指令保真**：确保初始用户指令在所有轮次中被完整执行
- **幻觉防御**：防止论文出现初始指令未涉及的事实、引用或方法
- **偏离检测**：量化论文与初始指令的偏离程度
- **回滚保障**：当偏离严重时，回滚至上一合规版本

## 二、初始指令快照机制

### 2.1 快照保存内容

在Pipeline启动时（第0轮），将初始指令完整保存为不可变快照，包含以下要素：

| 快照要素 | 内容 | 用途 |
|---------|------|------|
| 研究主题 | 用户指定的研究主题与范围 | 偏离检测的基准 |
| 研究问题 | 用户明确的研究问题（含子问题） | 主题一致性评估 |
| 理论框架 | 用户指定的理论框架或理论方向 | 方法幻觉检测 |
| 研究方法 | 用户指定的研究方法与数据来源 | 方法幻觉检测 |
| 核心概念 | 用户明确的核心概念与定义 | 事实性幻觉检测 |
| 目标期刊 | 用户指定的目标期刊格式 | 格式一致性检查 |
| 研究类型 | 用户指定的研究类型（量化/质性/混合/计算） | 方法适配检查 |
| 字数要求 | 用户指定的字数要求 | 字数控制基准 |
| 风格偏好 | 用户指定的写作风格偏好 | 风格一致性检查 |
| 禁止事项 | 用户明确禁止的内容或做法 | 禁止项检测 |

### 2.2 快照注入机制

每轮循环开始时，ConstraintInjector从快照中提取初始指令，注入到当前轮次所有Agent的指令中：

```
[第N轮循环开始]
  ↓
ConstraintInjector读取初始指令快照
  ↓
将初始指令注入各Agent的*_instruction字段
  ↓
同时注入上一轮的风格违规记录与偏离检测结果
  ↓
各Agent执行（在初始指令约束下）
  ↓
StyleGuard + InstructionConsistencyChecker双重检测
  ↓
[第N轮循环结束]
```

### 2.3 快照不可变性原则

- 初始指令快照在Pipeline运行期间**不可修改**
- 任何对初始指令的"优化"或"扩展"必须经用户确认后才能作为补充指令
- 补充指令与初始指令冲突时，以初始指令为准

## 三、幻觉检测规则

### 3.1 事实性幻觉

**定义**：论文中出现初始指令未涉及且无法从经验数据中推导的事实性陈述。

**检测规则**：
1. 提取论文中所有事实性陈述（统计数据、历史事件、政策内容、机构信息等）
2. 对照初始指令快照与经验数据，检查每个事实性陈述是否有依据
3. 标记无法追溯依据的事实性陈述为"事实性幻觉"

**常见事实性幻觉类型**：

| 类型 | 表现 | 示例 |
|------|------|------|
| 数据幻觉 | 编造初始指令未提供的统计数据 | "据统计，中国老年网民已达3.2亿"（初始指令无此数据） |
| 事件幻觉 | 编造初始指令未提及的历史事件 | "2019年某政策出台后..."（初始指令未提及该政策） |
| 机构幻觉 | 编造初始指令未涉及的机构信息 | "某平台日均活跃用户5亿"（初始指令无此信息） |
| 政策幻觉 | 编造初始指令未提及的政策内容 | "根据《XX条例》规定..."（初始指令未提及该条例） |

**处理规则**：
- 发现事实性幻觉：立即标记，要求Agent删除或替换为可追溯的依据
- 事实性幻觉属于**high严重程度**，触发回滚机制

### 3.2 引用幻觉

**定义**：论文中出现不存在的文献引用，或引用信息与实际文献不符。

**检测规则**：
1. 提取论文中所有文献引用（著者-年或脚注编号）
2. 对照参考文献列表，检查每个引用是否在列表中存在
3. 对参考文献列表中的每条文献，验证其真实性（作者、年份、期刊、页码）
4. 标记无法验证的引用为"引用幻觉"

**常见引用幻觉类型**：

| 类型 | 表现 | 检测方法 |
|------|------|---------|
| 文献不存在 | 引用了实际不存在的文献 | 在线数据库检索验证 |
| 信息错误 | 文献存在但作者/年份/页码错误 | 对照原始文献核实 |
| 张冠李戴 | 将A文献的观点归于B文献 | 对照原始文献核实观点归属 |
| 装饰性引用 | 引用但未实质性对话 | 检查引用后是否有分析性论述 |

**处理规则**：
- 发现引用幻觉：立即标记，要求Agent删除或替换为真实文献
- 单条引用幻觉：medium严重程度，警告并注入提醒
- 3条以上引用幻觉：high严重程度，触发回滚机制

### 3.3 方法幻觉

**定义**：论文中使用了初始指令未提及的研究方法或数据来源。

**检测规则**：
1. 提取论文方法部分的所有方法描述与数据来源
2. 对照初始指令快照中的"研究方法"与"数据来源"，检查是否一致
3. 标记初始指令未提及的方法或数据来源为"方法幻觉"

**常见方法幻觉类型**：

| 类型 | 表现 | 示例 |
|------|------|------|
| 方法幻觉 | 使用了初始指令未提及的方法 | 初始指令指定"深度访谈"，论文却出现"问卷调查" |
| 数据幻觉 | 使用了初始指令未提及的数据 | 初始指令指定"访谈数据"，论文却引用"平台API数据" |
| 样本幻觉 | 编造了初始指令未提供的样本信息 | 初始指令未提供样本量，论文却写"有效样本N=856" |
| 分析幻觉 | 使用了初始指令未提及的分析工具 | 初始指令未提及Nvivo，论文却写"使用Nvivo12编码" |

**处理规则**：
- 发现方法幻觉：立即标记，要求Agent删除或回归初始指令指定的方法
- 方法幻觉属于**high严重程度**，触发回滚机制

## 四、指令偏离检测

### 4.1 关键词覆盖率计算方法

**定义**：初始指令中的核心关键词在当前论文版本中的出现覆盖率。

**计算步骤**：
1. 从初始指令快照中提取核心关键词集合K={k1, k2, ..., kn}
2. 统计每个关键词ki在当前论文版本中的出现次数ci
3. 关键词覆盖率 = (出现次数>0的关键词数 / 总关键词数) × 100%

**示例**：
- 初始指令核心关键词：{跨文化传播, 平台算法, 可见性, 编码解码, UGC}
- 当前论文中出现的关键词：{跨文化传播, 平台算法, 可见性, 编码解码}（UGC未出现）
- 关键词覆盖率 = 4/5 × 100% = 80%

**阈值**：
- 覆盖率≥90%：通过
- 覆盖率70%-89%：medium偏离，警告
- 覆盖率<70%：high偏离，触发回滚

### 4.2 主题一致性评估方法

**定义**：当前论文版本的主题与初始指令指定主题的一致程度。

**评估步骤**：
1. 从初始指令快照中提取研究主题T_initial
2. 从当前论文版本的摘要、引言、结论中提取实际主题T_actual
3. 计算主题相似度（基于语义嵌入或关键词重叠）
4. 主题一致性 = 主题相似度 × 100%

**评估维度**：
- 研究对象一致性：论文研究的对象是否与初始指令一致
- 研究问题一致性：论文回答的问题是否与初始指令一致
- 理论框架一致性：论文使用的理论是否与初始指令一致
- 方法路径一致性：论文采用的方法是否与初始指令一致

### 4.3 偏离度计算公式

**综合偏离度**计算：

```
偏离度 = w1 × (1 - 关键词覆盖率) + w2 × (1 - 主题一致性) + w3 × 幻觉指数

其中：
- w1 = 0.3（关键词权重）
- w2 = 0.4（主题权重）
- w3 = 0.3（幻觉权重）
- 幻觉指数 = (事实性幻觉数 + 引用幻觉数×0.5 + 方法幻觉数×1.5) / 10
```

**示例**：
- 关键词覆盖率 = 80% → (1-0.8) = 0.2
- 主题一致性 = 85% → (1-0.85) = 0.15
- 事实性幻觉 = 1，引用幻觉 = 2，方法幻觉 = 0 → 幻觉指数 = (1 + 2×0.5 + 0) / 10 = 0.2
- 偏离度 = 0.3×0.2 + 0.4×0.15 + 0.3×0.2 = 0.06 + 0.06 + 0.06 = 0.18 = 18%

## 五、严重程度分级

### 5.1 分级标准

| 严重程度 | 偏离度 | 处理方式 |
|---------|--------|---------|
| low | <5% | 继续循环，记录偏离项供下一轮参考 |
| medium | 5%-15% | 警告，注入提醒，要求下一轮修正偏离项 |
| high | >15% | 立即终止当前轮次，回滚至上一合规版本 |

### 5.2 low严重程度处理（偏离度<5%）

**判定条件**：
- 关键词覆盖率≥95%
- 主题一致性≥95%
- 无事实性幻觉
- 无方法幻觉
- 引用幻觉≤1条

**处理方式**：
- 继续正常循环
- 在下一轮ConstraintInjector中注入偏离项提醒
- 记录偏离项至偏离日志

### 5.3 medium严重程度处理（偏离度5%-15%）

**判定条件**：
- 关键词覆盖率70%-94%
- 主题一致性85%-94%
- 事实性幻觉=0
- 方法幻觉=0
- 引用幻觉2-3条

**处理方式**：
- 在评审报告中标注偏离警告
- ConstraintInjector注入强提醒："当前论文偏离初始指令，需修正以下偏离项：[偏离项列表]"
- 要求对应Agent在下一轮优先修正偏离项
- 偏离项未在下一轮修正：升级为high严重程度

### 5.4 high严重程度处理（偏离度>15%）

**判定条件**：
- 关键词覆盖率<70%
- 主题一致性<85%
- 事实性幻觉≥1条
- 方法幻觉≥1条
- 引用幻觉≥3条

**处理方式**：
- 立即终止当前轮次
- 触发回滚机制，回滚至上一合规版本
- 在评审报告中标注严重偏离警告
- 要求人工介入确认是否调整初始指令

## 六、回滚机制

### 6.1 何时回滚

**触发条件**（满足任一即触发）：
1. 偏离度>15%（high严重程度）
2. 出现事实性幻觉且无法在当轮修正
3. 出现方法幻觉且无法在当轮修正
4. 引用幻觉≥3条且无法在当轮修正
5. 某维度评分较上一轮倒退超过3分
6. 连续2轮偏离度持续上升

### 6.2 如何回滚

**回滚流程**：
```
[检测到high严重程度偏离]
  ↓
暂停当前轮次所有Agent执行
  ↓
从版本管理器中检索上一合规版本
  ↓
将论文状态回滚至上一合规版本
  ↓
在回滚版本基础上，注入偏离修正指令
  ↓
重新启动当前轮次
  ↓
[回滚完成]
```

**回滚操作记录**：
- 记录回滚触发原因（偏离类型、偏离度）
- 记录回滚源版本与目标版本
- 记录回滚时间戳
- 将回滚原因注入下一轮ConstraintInjector

### 6.3 回滚到哪个版本

**版本选择规则**：

| 情况 | 回滚目标版本 |
|------|-------------|
| 第1轮即出现high偏离 | 回滚至初始指令快照（第0轮），要求重新生成 |
| 第N轮出现high偏离（N≥2） | 回滚至第N-1轮的合规版本 |
| 第N-1轮也不合规 | 逐级回滚至最近的合规版本 |
| 无合规版本可回滚 | 终止Pipeline，要求人工介入 |

**合规版本判定标准**：
- 偏离度<5%（low严重程度）
- 无事实性幻觉
- 无方法幻觉
- 引用幻觉≤1条
- 各维度评分无倒退

### 6.4 回滚次数限制

- 单轮最多回滚2次：超过2次则终止Pipeline，要求人工介入
- 全Pipeline最多回滚5次：超过5次则输出当前最佳版本+未解决问题清单
- 回滚后连续3轮无偏离：重置回滚计数器

### 6.5 回滚与增量修改的协调

回滚机制与增量修改机制（IncrementalRevision）协调运作：

| 场景 | 处理方式 |
|------|---------|
| 回滚至上一版本 | 上一版本的FROZEN章节保持冻结，ACTIVE章节重新激活 |
| 回滚后重新执行 | 仅修改导致偏离的章节，不影响其他已通过章节 |
| 回滚导致章节状态变化 | 更新章节状态管理器，重新计算冻结条件 |

## 七、指令一致性检查清单

每轮循环结束时，执行以下检查：

### 7.1 初始指令执行检查
- [ ] 初始指令中的研究主题是否在论文中完整体现
- [ ] 初始指令中的研究问题是否在论文中完整回答
- [ ] 初始指令中的理论框架是否在论文中完整应用
- [ ] 初始指令中的研究方法是否在论文中完整执行
- [ ] 初始指令中的核心概念是否在论文中完整定义
- [ ] 初始指令中的目标期刊格式是否在论文中完整遵循
- [ ] 初始指令中的字数要求是否得到满足
- [ ] 初始指令中的禁止事项是否被遵守

### 7.2 幻觉检测检查
- [ ] 论文中所有事实性陈述是否有据可查
- [ ] 论文中所有文献引用是否真实存在
- [ ] 论文中所有方法描述是否与初始指令一致
- [ ] 论文中所有样本信息是否与初始指令一致

### 7.3 偏离检测检查
- [ ] 关键词覆盖率是否≥90%
- [ ] 主题一致性是否≥90%
- [ ] 偏离度是否<5%
- [ ] 是否存在持续上升的偏离趋势

### 7.4 回滚必要性检查
- [ ] 是否触发回滚条件
- [ ] 回滚目标版本是否可用
- [ ] 回滚后是否需要人工介入

## 八、指令一致性日志

每轮循环记录以下指令一致性日志：

```yaml
round: N
timestamp: YYYY-MM-DD HH:MM:SS
instruction_consistency:
  keyword_coverage: XX%
  topic_consistency: XX%
  hallucination:
    factual: X
    citation: X
    method: X
  deviation_degree: XX%
  severity: low/medium/high
  action: continue/warn/rollback
  rollback:
    triggered: true/false
    source_version: vX
    target_version: vY
    reason: "..."
```

日志用于：
- 跨轮次偏离趋势监控
- 回滚决策依据
- Pipeline运行诊断
- 人工介入时的状态报告
