## 1. 执行与证据规则

- 每例记录状态 `not_run/pass/fail/blocked`、版本/环境、具体命令或人工步骤、实际结果和证据位置。没有实际运行记录不得标 pass。
- R0/R1 标注表示分阶段验收：R0 完成已明确的隔离/契约/诚实失败子集，R1 再完成恢复/完整工作区等要求；不能用 R0 基础通过代替 R1 完整通过。
- 自动化测试用合成或已授权材料、隔离数据与模型/工具替身。外部调用替身验证契约，不能用来证明真实模型学术质量。
- 模型输出格式正确不等于论文质量正确。工程验证、受控真实模型验证和人工评审的证据分别保存。
- 公共元数据、摘要、全文片段和模型推断分别验收。数据库归属检查和实际前端操作都不能由界面上的状态文字替代。
- 既有账号、支付、限流与上传安全测试继续运行；本矩阵是增量验收，不替代既有回归。

## 9. 发布验收清单

R0：当前实际交付前端的关键用户流程通过；无模拟文献冒充、无假保存/假完成、无跨用户文件读写、无失败重复扣额；未接通能力准确关闭；既有支付与权限回归通过。

R1：所有对应工程用例有证据；同一项目完成上传—诊断—定位—建议—采纳—导出—继续；全文文本覆盖可证明；重启、取消、删除、故障与重试不会破坏资料/权益；唯一构建产物经过浏览器验收；迁移 dry-run 和回退演练通过。实际模型与人工评价尚未验证的质量边界必须明确展示。

R2：真实任务评估和人工盲评完成，报告样本、误报与局限；扩展能力按独立门槛开放。图表、Browser Agent、普通用户执行或全学科能力不能因主流程通过而自动宣告可用。

阶段结果记录至少包括：PRD 版本、代码版本、AT ID 列表、实际运行环境、命令/步骤、结果、成果证据、剩余限制、数据迁移与回退情况。不能用“已完成优化”“测试均通过”替代具体记录。
